⏺ Complete PDF Upload Workflow: SmartTrendTracer → Papers → Upload PDF → marker_server

  Here's the complete flow:

  1. Frontend: User Uploads PDF

  - Component: PaperUploadModern.tsx
  - User drags/drops or selects PDF file
  - Sends POST request to http://localhost:8000/api/papers/upload
  - Shows upload progress with visual feedback

  2. Backend: Paper Upload API (papers.py:80-131)

  - Receives PDF file at /api/papers/upload
  - Validates file (PDF type, <50MB size)
  - Saves PDF to disk via paper_service.save_pdf_file()
  - Creates Paper record in DB with status "Processing..."
  - Returns immediate response with paper ID
  - Schedules background task: process_pdf_complete()

  3. Background Processing (papers.py:133-207)

  - Runs process_pdf_complete() asynchronously
  - Calls pdf_processor_service.process_pdf() with paper_id

  4. PDF Processor Service (pdf_processor_service.py:183-358)

  - Checks available processors in order of preference
  - Default: Marker Service ONLY (no fallback in auto mode)
  - Calls _process_with_marker_service() which delegates to AsyncPDFProcessor

  5. Async PDF Processor (async_pdf_processor.py:143-247)

  - Creates multipart form data with PDF file
  - Sends POST to http://localhost:8002/convert with:
    - PDF file
    - paper_id (for image management)
    - Configuration flags (use_llm=true, debug=true, etc.)
    - 20-minute timeout for processing

  6. Marker Server Processing (marker_server.py:240-371)

  - Receives PDF at /convert endpoint
  - Saves PDF to temp directory
  - Runs marker_single CLI tool via PTY for real-time progress
  - Extracts images and markdown
  - If paper_id provided:
    - Uses ImageManager to persist images to data/paper_images/
    - Rewrites image URLs from filesystem paths to API endpoints
  - Returns JSON response with markdown, metadata, and image info

  7. Response Flow Back

  - Marker server → Async PDF Processor (cleans content, adds metadata)
  - → PDF Processor Service (logs success/failure)
  - → Background task updates Paper record with:
    - Extracted markdown content
    - Processing status
    - Metadata (title, abstract, authors)
    - Processor used ("marker_service")
  - → Paper saved to database
  - → Added to RAG index for search

  8. Frontend Updates

  - Upload component shows success checkmark
  - Calls onUploadComplete callback
  - Parent component (PapersDashboard) refreshes paper list
  - User sees processed paper with extracted content

  Key Points:

  - Asynchronous: Upload returns immediately, processing happens in background
  - Image Handling: Images extracted and stored with paper_id reference
  - URL Rewriting: Image paths converted from filesystem to API URLs
  - No Fallback: In auto mode, only Marker Service is used (must work or fail)
  - Error Handling: Failures update paper record with error message
