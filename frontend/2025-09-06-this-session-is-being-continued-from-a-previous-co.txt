⏺ Great observation! The current "scroll to top on page change" creates an awkward user flow. Here are some UX ideas to reduce mouse movement:

  📍 Position-Aware Navigation Ideas

  1. Smart Scroll Position

  - Remember where user was scrolling when they hit "Next"
  - If they were at bottom 20% of page → start new page at top
  - If they were at top 50% of page → start new page where they left off
  - Maintains reading flow better

  2. Floating Navigation Bar

  - Fixed navigation buttons that follow scroll position
  - Always visible at bottom-right or top of viewport
  - No need to scroll to bottom to navigate
  - Could be compact: ← 3/12 → format

  3. Reading Progress Navigation

  - Navigation appears when user reaches bottom 10% of page content
  - Fade in "Next Page" button as they approach end
  - Disappears if they scroll back up
  - Natural reading flow trigger

  4. Contextual Page Breaks

  - Show a preview of next page content at current page bottom
  - "Continue reading..." with smooth transition
  - Like Medium's "more from this author" but for same document
  - Reduces jarring page switches

  5. Scroll-Through Pages

  - Keep small amount of next page content visible at bottom
  - When user scrolls past current page end, smoothly load next page
  - Infinite scroll feeling but with page performance benefits
  - Maintains scroll momentum

  6. Keyboard-First Design

  - Space bar = next page (like PDF readers)
  - Shift+Space = previous page
  - PgDn/PgUp already work
  - Reduce mouse dependency entirely

  7. Reading Position Memory

  - Remember approximate reading position (% through page)
  - When returning to a page, start at last reading position
  - Like Kindle's "furthest reading position"
